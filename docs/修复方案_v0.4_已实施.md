## 二、先修"验证基建"（否则改完也没法证明）

修 bug 前先解决了三个"测不出来"的坑，这些本身也是这次能收敛的原因：

1. **真实扩展会污染测试页**
   `manifest.json` 的 `content_scripts.matches` 是 `http://*/*`，所以在 `localhost` 上
   **已装扩展的 content script 也在跑**，和被测 bundle 抢同一个 `#__wsa_host__`——
   探针读到的是旧实例的面板，改动看起来"没生效"。
   → 解法：`tests/harness_shell.html` 把 harness 放进 **`srcdoc` iframe**（`about:blank` 来源）。
   扩展未开 `match_about_blank`，不会注入；同时把 host id 参数化为
   `documentElement.dataset.wsaHostId`，两边永不撞车。探针会先自检并回报
   `extensionInjected:false`，隔离失效时立刻可见。

2. **`tools/cdp_eval.py --file` 不可用**
   `--expr` 是 `required=True`，`--file` 永远轮不到；且默认 30s 读超时不够逐字段探测。
   → 新增 `tools/cdp_file.py`（从文件读 JS 表达式，免转义/免中文乱码），并给
   `cdp_eval.py` 加 `--read-timeout`。

3. **测试会读到真实字典**
   早期垫片键与页面直连，`localStorage` 里留下了真实 PII。
   → 垫片改用独立键（`__wsa_harness_store_v2__` / `__wsa_ltest_store__`），
   并在探针里只播假名替身；已清理浏览器里遗留的测试键。

## 三、改了什么（P0 / P1）

### P0-1 兄弟元素"内部含控件"被整块跳过 → 误杀真标签

**原因**：跳过条件是递归的 `ps.querySelector('input,textarea,select')`，
于是 `<div class="label">所学专业<select>…</select></div>` 这种
**"专业/学校用下拉选"的主流形态**被当成"另一个字段"整块丢弃。

**改法**（`content.js · siblingHasField`）：只把**可输入文本的可见控件**当作另一个字段——
`input[type=hidden]`、`disabled`、不可见的都不算，`select` 也不算（它常与标签同容器）。

```js
const TEXTY_TYPES = ['', 'text', 'search', 'tel', 'email', 'url', 'number', 'password'];
function siblingHasField(ps) {
  const isTexty = (c) => TEXTY_TYPES.includes((c.type || '').toLowerCase()) && isVisibleControl(c);
  if (ps.matches && ps.matches('input,textarea')) return isTexty(ps);
  if (ps.matches && ps.matches('select')) return false;      // select 常与标签同容器
  for (const c of ps.querySelectorAll('input,textarea')) if (isTexty(c)) return true;
  return false;
}
```

### P0-2 写入"假成功" → 三态回读核对

**原因**：`setNativeValue` 无条件 `return true`，`fill` 便报绿「已填入」；
被 `maxlength` 截断、被格式化、被框架还原全都报成功。

**改法**（`content.js · readBack / setNativeValue / setSelect / fill`）：
写完立刻回读比对，分三态给不同 toast ——
`ok`「已填入…请目检」／`changed`「已填入，但被页面改写为「X」（原文「Y」），请核对该框」／
`reverted`「填入未生效（页面已还原该框），请手动输入」；再叠加 `nomatch`（下拉无匹配项）。

### P0-3 标签采集改为"带可信度的候选 + 甄别"

原来的 `haystack` 是"按插入顺序 push，谁先谁赢"，于是
**校验文案 `邮箱格式不正确` 抢在真标签 `电子邮箱` 前面**。
现在改为 `collectCandidates` 打分，按可信度取：

| 来源 | 分 |
|---|---|
| `label[for]` / `closest(label)` | 95 / 90 |
| `branchScan`（旁支兄弟标签） | 75 起，逐层 -3 |
| `td` 前兄弟 | 70 |
| `title` / `name` / `legend` | 55 / 45 / 50 |
| `placeholder` | 40 |
| `prevSib` / 祖先文本 | 30 / 20（最低） |

同时剔除：`HINT_CLASS`（`err/error/tip/hint/help/note…`）、
`looksLikeValidation`（`格式/不正确/请填写/必填…`）、`isNoise`（`0/200`、纯符号）。
`haystack()` 仍返回**字符串数组**（保持 `WSA.matchConcepts/buildRows` 接口不变），
只是按可信度降序 —— 于是 `matchConcepts` 取 `hits[0]` 时天然优先真标签。

### P1-1 标签长度 12 字上限 + 占位符剥壳 + 裸 id

- 长度上限 12 → **24**（中文标签带括号说明极易超 12 字）；
- `isGenericHint` 不再被当成"整串必须等于占位符"：新增 `stripVerb` 剥壳，
  `请输入验证码` → `验证码`；纯 `请输入` 仍然判为无信息；
- 尾部 `必填/选填` 标记剥掉（`紧急联系人电话必填` → `紧急联系人电话`）；
- **裸 id 绝不作为标题**：`firstLabelFrom` 只取中文标签（次选有字母的英文标签），
  否则返回空 → 卡片显示「未识别」（不再出现 `a4`/`field_2384` 这种标题）。

### P1-2 select 歧义不许静默选错

**原因**：`opts.find(x => x.text.includes(nv) || nv.includes(x.text))` 会随便命中第一个——
存 `英语`、选项有 `英语四级/英语六级/英语专业八级`，就静默选了四级。

**改法**（`resolveSelectOption`）：精确归一化唯一命中 → 填；
部分匹配**唯一**命中 → 填；部分匹配**多个** → 照填第一个但 toast 明确列出全部相近选项
并标为告警：「实际选中「英语四级」，但选项有多个相近值（英语四级 / 英语六级 / 英语专业八级），请务必核对」。
比"不填"更实用，同时不撒谎。

### P1-3 过度匹配抑制（顺带发现的安全问题）

**发现**：字典里没存紧急联系人电话时，「紧急联系人电话」框会**列出本人手机号**
（`紧急联系人:5` 之上还捎带了 `手机号:2`）——用户很可能把自己的号码当成紧急联系人填进去。

**改法**（`matcher.js · buildRows`）：当低分概念的匹配词**只是高分概念匹配词的子串**
（`号码 ⊂ 身份证号码`）时抑制它；但若低分概念有"等于整串"的匹配词则不抑制
（`联系电话` 的 `电话` 正等于整串 → 仍命中）。

实测效果（隔离环境，`emergency` 无值、`phone` 有值）：

| 字段 | 修复前 | 修复后 |
|---|---|---|
| 紧急联系人电话 | 列出本人手机号 ⚠️ | 无候选 + 提示"已识别为「紧急联系人」但本机还没存过这类值" |
| 身份证号码 | 身份证号 + 手机号 | 只有身份证号 |
| 毕业院校 | 毕业院校 + 毕业时间 | 只有毕业院校 |
| 联系电话 | 手机号 | 手机号（**未被误杀**） |

### P2 数据质量与体验

- **`remember()` 改为"读改写 + 共享清洗"**：`get → 合并 → cleanDict → set`，
  修掉与「字典管理」页并发保存互相覆盖；`cleanDict` 提到 `matcher.js`
  由 `content.js` 与 `options.js` 共用（两条写入路径产出一致）。
- **拒绝垃圾键**：标签识别失败时不再存成 `custom: "a4"`，改为提示去字典管理页手动添加。
- **空候选提示更准**：命中概念但没存过值 → "已识别为「X」，但本机还没存过这类值"。
- host 版本探针 0.3 → **0.4**（`integration.html` 断言同步更新）。

## 五、复现与验收

```powershell
# 0) AI 浏览器需在运行（桌面 start-ai-browser.bat，端口 9223）
# 1) 仓库根目录起测试服务
python -m http.server 8777 --bind 127.0.0.1

# 2) 三个自带套件（注意加 ?v= 破缓存，否则读到旧页）
python tools/cdp_eval.py --url "http://localhost:8777/tests/unit.html?v=1"        --expr "window.__report()"
python tools/cdp_eval.py --url "http://localhost:8777/tests/integration.html?v=1" --expr "window.__itest()"
python tools/cdp_eval.py --url "http://localhost:8777/tests/labels.html?v=1"      --expr "window.__ltest()"

# 3) 隔离 harness（免重启，改动即刻生效；会自检扩展是否被隔离）
python tools/cdp_file.py --file _probe_shell.js --url "http://localhost:8777/tests/harness_shell.html?v=1" --read-timeout 200
```

**验收标准**：unit `fail:0`、integration `fail:0`、labels `fail:0`、
隔离 harness 四段全绿（标签 19/19、写入 4/4、select 歧义 OK、危险场景 3/3）。

## 六、还剩什么（未改，建议后续）

| 项 | 说明 | 建议 |
|---|---|---|
| 滚动跟随 | `window.addEventListener('scroll', …, true)` 收不到**模态框/内部 div** 的滚动（scroll 不冒泡），表单在可滚动抽屉里时卡片会"飘走" | 改挂 `document`，或用 `ResizeObserver` + rAF 跟踪 `state.el.getBoundingClientRect()` |
| 固定头尾遮挡 | `position()` 只按 `innerHeight` 收边，未避让 sticky 表头/底部按钮条 | 用 `getBoundingClientRect` 探测并让位 |
| `all_frames: true` | 每帧一个 host；iframe 表单可能同时出现两个卡片 | 实测一个 iframe 网申站后再定；必要时只在顶层帧渲染 |
| 卡片遮挡 select | 卡片优先弹右侧，可能盖住 `<select>` 原生下拉 | select 类型优先放下方 |
| 弱命中阈值 | `shingleScore ≥ 0.5` 对短标签偏松（`证件照上传` 会 `≈` 到身份证号） | 已有 `≈` 前缀提示，可按需提高阈值 |
| iframe 内 ATS | 尚未在真实 iframe 网申站验证 | 建议拿真实站各测一次 |

> 说明：v0.4 的所有结论都来自**隔离环境 + 真实源码**，而非真实网申站。
> 真实站首次使用请仍按原设计「填完目检」；如遇标签取错，卡片会显示它以为的标签名，
> 可直接对照判断，并把该说法补进 `concepts.js`。
