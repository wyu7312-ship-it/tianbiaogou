## 二、你这次修的那条 bug（旁支兄弟标签）——方向对，但有 4 个漏口

修复思路（沿祖先链找"路径元素的前兄弟"）是对的：`a1 姓名`、`a3 毕业院校`、`d1/d4` 都救回来了。
实测失败的 4 类如下（`_ats_report.txt` 有原始数据）。

### B1. ⚠️ 兄弟元素"内部含控件"就被整块跳过 —— 误杀真标签（最严重）

`content.js` branchScan 内的判据：

```js
if (ps.matches('input,textarea,select') || ps.querySelector('input,textarea,select')) continue;
```

本意是"兄弟里是另一个字段就跳过防串标签"，但 `ps.querySelector()` 是**递归**的，
于是这些**合法标签**被整块丢弃：

| 用例 | 标签 DOM | 结果 |
|---|---|---|
| `b2` 政治面貌 | `<div class="label">政治面貌*<input type="hidden"></div>` | 标题退化成 `b2` |
| `b3` 所学专业 | `<div class="label">所学专业<select>…</select></div>` | 标题退化成 `b3` |

实测 branchScan 轨迹（`_ats_dbg_report.txt`）：

```
=== b2 ===  lvl0 ps=DIV.label ctrl=true  len=5 txt=政治面貌*     ← 被 continue 掉
=== b3 ===  lvl0 ps=DIV.label ctrl=true  len=4 txt=所学专业       ← 被 continue 掉
```

> 真实影响：**"专业/学校用下拉框选"是国内网申的主流形态**，这类标签几乎必挂。
> 注意 `select` 还是本扩展明确支持的控件类型（`isEditable` 认 SELECT），却反过来把自己的标签判成"另一个字段"。

**修法**：跳过条件改成"该兄弟**自身就是可见可编辑控件**，或**包含可见可编辑控件**"——
`input[type=hidden]`、`display:none`、`aria-hidden`、`disabled` 一律不算。例如：

```js
const hasCtrl = (n) => {
  if (n.matches('input,textarea,select')) {
    const t = (n.type || '').toLowerCase();
    if (t === 'hidden' || n.disabled) return false;
    return n.offsetParent !== null || n.getClientRects().length > 0;
  }
  return Array.from(n.querySelectorAll('input,textarea,select')).some((c) => {
    const t = (c.type || '').toLowerCase();
    return t !== 'hidden' && !c.disabled && (c.offsetParent !== null || c.getClientRects().length > 0);
  });
};
if (hasCtrl(ps)) continue;
```

同时**兜底**：`el.closest('label')` 之外再补一条"祖先链上最近的 label"，因为 `b1`（`<label>身份证号码 <input></label>`）
是靠 `closest('label')` 救的，若 ATS 写成 `<label>…</label>` 包住但中间隔了一层，就只剩 `b1` 这条路径了。

### B2. 标签超过 12 字被丢弃，且 `isGenericHint` 在这里帮倒忙

| 用例 | 标签 | 结果 |
|---|---|---|
| `a4` | `是否服从调剂（请慎重选择并确认）`（16 字） | 标题退化成 `a4`，0 候选 |

两个叠加原因：

1. `t.length <= 12` —— 中文标签带括号说明极易超过 12 字；
2. `isGenericHint('是否服从调剂（请慎重选择并确认）')` 返回 **true**（归一化后含"请…选择"，撞上 `/^(请)?(输入|选择|填写|填入|写)?(内容|信息)?$/` 的宽松匹配）。

**修法**：
- 长度上限放宽到 ~24（中文标签的安全区），或先剥掉尾部括号说明再判长度；
- 剔噪与长度判断**分开**：`isGenericHint` 只用于"纯占位符"，不要拿它否决一个含实质名词的长标签；
- `是否服从调剂` 这类"是否…/有无…/能否…"句式应加入白名单。

### B3. 错误提示抢位 —— 卡片标题变成"邮箱格式不正确"

```
=== c1 ===  haystack: [prevSib0] 邮箱格式不正确   [branchScan(L0)] 电子邮箱
            卡片标题 = 邮箱格式不正确        ← prevSibling 先入，firstLabel 取 parts[0]
```

`haystack` 里 `prevSibling`（第 94-95 行）排在 `branchScan` 之前，而 `firstLabel` 取的是
"第一个非通用提示、且含中文的"项，于是校验错误文案赢了真标签。

**修法**：给每条来源打**可信度权重**，`firstLabel` 按权重取，而不是按插入顺序：

```
label[for] / closest(label) / legend  >  td 前兄弟 / branchScan  >  prevSibling  >  placeholder / id
```

并把 `.err/.error/.invalid/.help-block/.tip/.hint` 这类 class 的兄弟降权或直接排除。

### B4. 占位符没被剥壳，仍然泄漏成标题

```
=== f2 ===  卡片标题 = 请输入验证码
```

`isGenericHint` 只认**整串等于**"请输入/请选择"，不认"请输入 + 内容"。
`请输入验证码`→应取 `验证码`；`请输入姓名`→应取 `姓名`。

**修法**：把"剥壳"和"判空"拆开：

```js
function stripVerb(s) { return String(s || '').replace(/^(请)?(输入|填写|填入|选择|请选择)\s*/, '').trim(); }
// 判空：stripVerb(s) 为空 或 仅剩"内容/信息/必填/选填" → 视作无信息
// 取值：用 stripVerb(s) 的结果进 haystack（而不是丢弃整串）
```

### B5. 标题退化时显示裸 id（`a4` / `b2` / `b3` / `f1`）

`haystack` 把 `el.id` 原样放进 parts，`firstLabel` 会退到它。
真实页面 id 常是 `field_2384` / `input-17` 这类无意义串。

**修法**：`firstLabel` 里排除"纯 ASCII 且无中文"的 id（除非它像 `realName` 这种驼峰语义 id，
可作为**最低优先级**候选，但绝不单独成为标题）。同时**无标签时应显示"未识别"**，而不是显示 id。

## 三、另外几处可能出问题的地方（静态复核 + 机制推断）

### C1. `setNativeValue` 恒返回 true —— "已填入"可能是假成功 ⚠️

```js
function setNativeValue(el, value) { …; return true; }   // 无条件 true
```

于是 `fill()` 必弹绿色 toast「已填入…请目检该框内容」。
但目标页可能有：`maxlength` 截断、`inputmode`/格式化（手机号自动加空格）、
受控组件在 `onChange` 后回写规范化值、或校验失败后清空。

**建议**：写入后回读比对并给出**三态**提示：

```js
const after = el.value;
if (after === value) toast('已填入…');
else if (after) toast('已填入但被页面改写为「' + after + '」，请核对该框', true);
else toast('填入未生效（页面已还原该框），请手动输入', true);
```

`setSelect` 同理（`setter.call` 后回读 `el.value`）。

### C2. `setSelect` 的包含匹配可能选错项

```js
opts.find(x => norm(x.text).includes(nv) || (nv.length >= 2 && nv.includes(norm(x.text))))
```

- 存的值是 `硕士`，选项是 `硕士研究生` → 命中（好）；
- 但存 `英语`、选项有 `英语四级`/`英语六级` → 会**随便命中第一个**，静默填错；
- 反向包含（`nv.includes(x.text)`）更危险：存 `中共党员（含预备）` 可能命中 `党员`。

**建议**：包含匹配命中多项时**不要自动选**，改为在卡片里把候选列出来让人点；
或至少把命中的选项文本回显到 toast 里让人核对。

### C3. `remember()` 未经 `cleanDict()`，且与 options 页互相覆盖

- options.js 保存前走 `cleanDict()`（去空值/去空别名/trim），content.js 的 `remember()` 直接
  `chrome.storage.local.set({wsa_dict_v2: dict})`，**两套写入路径不一致**，空别名/空值可能入库；
- `remember()` 读的是自己内存里的 `dict`，若 options 页同时保存，会**最后一次写入覆盖**对方（丢数据）。

**建议**：抽一个 `WSA.cleanDict()` 供两边共用；`remember()` 改为
`get → 合并 → clean → set`（读改写），而不是用内存快照直接覆盖。

### C4. "记住"可能存下垃圾键

`remember()` 用 `firstLabel()` 作 `custom` 的键。当标签识别失败（如 `a4`/`b2`/`b3`），
会存成 `custom: "a4"` 这种无意义条目，**污染字典且下次永远匹配不上**。

**建议**：`rawLabel` 为裸 id / 通用提示 / 长度 < 2 时，拒绝保存并提示
"未识别出该框标签，请先到字典管理页添加字段名"。

### C5. 滚动监听挂 `window`，弹层在模态框内滚动时不会跟随

```js
window.addEventListener('scroll', () => { … position(); }, true);
```

`scroll` 事件**不冒泡**，`window` 上的捕获监听只能收到**文档级**滚动。
网申页大量使用"表单放在可滚动模态框/抽屉里"，此时滚动模态框内容，
输入框在动、卡片不动（卡片看起来"飘走"）。

**建议**：改用 `document.addEventListener('scroll', …, true)`（capture 能在 document 收到任意元素滚动），
或用 `ResizeObserver` + `requestAnimationFrame` 节流地跟踪 `state.el.getBoundingClientRect()`。

### C6. `position()` 不避让固定头/底栏

`top` 只按 `window.innerHeight` 收边，没有减掉吸顶 header / 底部按钮条的高度。
在有 `position:sticky` 表头的 ATS 页，卡片可能被压在表头下。

### C7. `all_frames: true` + 每帧 `#__wsa_host__`

`manifest.json` 是 `all_frames: true`，每个 iframe 都会注入一份 content script，
各自建 `id="__wsa_host__"`（同 id 在不同文档里合法，但）：
- 若表单在 iframe 内、外层也有可编辑元素，可能**同时出现两个卡片**；
- 外层聚焦时，iframe 内的卡片不一定收到 `focusin`，可能留下**残影**。

**建议**：实测一个 iframe 表单站（不少 ATS 用 iframe 嵌问卷）确认；必要时只在顶层帧渲染卡片，
跨帧用 `postMessage`（注意这条不违反"零联网"，但要在 AGENTS.md 里说明白）。

### C8. 弹卡可能盖住 `<select>` 的原生下拉

卡片优先放在输入框**右侧**（v0.2 的设计），但 `select` 的原生选项面板通常向右下展开。
点中 select 时卡片正好盖在选项上，用户会点错。建议 `select` 类型优先放下方或左上。

## 四、优先级建议

| 级别 | 问题 | 理由 |
|---|---|---|
| **P0** | B1 兄弟含控件误杀（select/hidden） | 下拉框选专业/学校是国内网申主流形态，必挂 |
| **P0** | C1 写成功假报 | 直接影响"填对没填对"的判断，是核心安全承诺 |
| **P1** | B2 长度 12 字上限 + hint 误判 | 长标签（含括号说明）成片失效 |
| **P1** | B3 错误提示抢位 | 真标签被覆盖，候选全错 |
| **P1** | C2 select 包含匹配选错 | 静默填错，比不填更糟 |
| **P2** | B4 占位符剥壳 / B5 裸 id 标题 | 影响可读性与"记住"质量 |
| **P2** | C3 双写入路径不一致 / C4 垃圾键 | 数据长期质量 |
| **P3** | C5 滚动跟随 / C6 固定头 / C7 iframe / C8 select 遮挡 | 体验与边缘场景 |

## 五、复现方式（AI 浏览器 CDP）

```powershell
# 1) AI 浏览器（端口 9223）需在运行：双击桌面 start-ai-browser.bat
# 2) 起本地测试服务（仓库根目录）
python -m http.server 8777 --bind 127.0.0.1

# 3) 两个自带套件
python tools/cdp_eval.py --url http://localhost:8777/tests/unit.html        --expr "window.__report()"
python tools/cdp_eval.py --url http://localhost:8777/tests/integration.html --expr "window.__itest()"

# 4) ATS 布局逐字段探针（见 tools/probe/，探针脚本与 dump 一律放子目录）
python tools/cdp_file.py --file tools/probe/shell.js --url http://localhost:8777/tests/harness_shell.html --wait 3 --read-timeout 200
```

新增文件：`tests/atsform.html`（ATS 布局用例页）、`tests/labels.html`（回归套件）、
`tests/harness_shell.html` + `tests/harness.js`（隔离 harness）、
`tools/probe/`（探针脚本与 dump 目录）、`tools/cdp_file.py`（从文件读 JS 表达式，免转义）。

> ⚠️ 目录约定（2026-09 实测）：**Chrome 拒绝加载目录内含 `_` 开头文件的未打包扩展**
> （`Filenames starting with "_" are reserved for use by the system`）。
> 因此探针 dump 只能写进 `tools/probe/dump/`，仓库根目录不得出现 `_*` —— 否则扩展装不上。

> 注：`tools/cdp_eval.py` 的 `--file` 参数因 argparse 里 `--expr` 为 required 而无法独立使用（既有小缺陷），
> `tools/cdp_file.py` 是绕开它的包装器；另给 `cdp_eval.py` 补了 `--read-timeout`（真实页面逐字段探测会超 30s 默认读超时）。
