> 一个 Chrome 扩展。点一下输入框，旁边弹出你存过的值，点一下填进**这一个**框。
> 数据只在你本机，代码不联网。

---

## 先说为什么有这东西

我是个毕业狗，正在秋招。

网申填表这件事，谁填谁知道。同一份简历，在几十个招聘系统里翻来覆去地敲。姓名、手机号、身份证、学校、专业、学历、毕业时间、政治面貌、籍贯、民族……一遍又一遍。

最烦的是每个站的字段叫法还不一样：

- 手机号 / 手机号码 / 移动电话 / 联系电话 / 联系方式 / Contact Number
- 毕业院校 / 学校 / 就读学校 / 院校 / 毕业学校
- 姓名 / 真实姓名 / 考生姓名

浏览器的自动填充在这种页面上基本是废的：它按字段名精确匹配，人家写"移动号码"它就失忆了。而且一张表里好几个"姓名"——本人、母亲、父亲、紧急联系人，它根本分不清，一填就串。

还有些系统更离谱，学历学位专业全给你做成下拉框，选项文字跟你脑子里想写的那几个字还常常对不上。

填到第三十家的时候人已经麻了。于是我用 AI 帮忙把这一套写了出来——概念表匹配、人称区分、点选只填当前框。现在填一家大概两三分钟。

## 它具体怎么做的

### 一、点输入框 → 弹卡片 → 你点哪行填哪行

不搞"一键灌满整张表"那种。就三个动作：

1. 你点中一个输入框
2. 卡片在旁边弹出来，列出它认为这个框该填的候选值
3. 你点其中一行（或者按 `↑` `↓` 再回车），值就填进**当前这一个框**

为什么不批量填？因为网申表一旦填错一个位置，后面全歪，而且很多表的字段顺序是动态的，批量填必错。宁可你多按一下。

卡片可以拖标题栏挪位置（表单选项经常弹在框下方，挡住视线），双击标题栏回到自动定位。

### 二、字段叫法不一样怎么认

`concepts.js` 里是一张"概念 → 中英同义词"的表。每个概念长这样：

```js
{ id: 'phone', label: '手机号', person: true,
  zh: ['手机', '电话', '号码', '移动'],              // 中文近义核词
  en: ['phone', 'mobile', 'tel', 'contactnumber'] }  // 英文一律小写、去空格
```

你点中框的时候，它会去读这个框附近的文字信号——`<label for>`、placeholder、紧邻的兄弟元素、表格单元格前面的那一格，谁行谁上。然后拿这些文字去概念表里找，命中了就弹那个概念的候选值。

所以"移动号码"、"联系电话"、"Contact Number"最后都会归到同一个「手机号」概念，你不用管网站怎么叫。

### 三、一个"姓名"框背后有好几个人

这是我最需要的一个功能。

本人姓名、母亲姓名、父亲姓名、紧急联系人——四个概念上都是"姓名"，但值完全不同。所以存值的时候可以打**人称标签**：

- 存的时候标明这是本人的、还是母亲的、还是紧急联系人的
- 点中姓名框，卡片把所有候选**全都列出来**并标注是谁的，你自己挑
- 它不会替你猜。会猜的自动填充，就是串信息的元凶

识别标签里的"母亲/父亲/配偶/紧急联系人"这类限定词是靠 `concepts.js` 里的 `WSA_QUALIFIERS` 做的。

### 四、认不出来的框怎么办

认不出来也不耽误用。手动把值打进去，然后点卡片底部的 **「＋ 记住」**：

- 它会把当前框的值存下来
- 同时把这个框的标签文字记成别名
- **下次遇到同类框就自动有候选了**

所以每个陌生字段的第一次代价只是多点一下，之后就好了。用得越久越顺手。

## 安装

Chrome 152 起，命令行 `--load-extension` 已经被侧载保护静默忽略了，别再试那条路。只能手动加载：

1. 把仓库 clone 或用 Code → Download ZIP 下到本地任意目录
2. Chrome 打开 `chrome://extensions`
3. 右上角打开**开发者模式**
4. 点**「加载已解压的扩展程序」**，选中本仓库根目录（**含 `manifest.json` 的那一层**）
5. 装好后先去扩展的**「详情 → 扩展程序选项」**，会看到初始化的向导

> ⚠️ 有一点容易踩：**仓库目录里不能有文件名以 `_` 开头的文件**。
> Chrome 规定 `_` 是系统保留前缀（留给 `_locales` 之类），会直接报
> `Filenames starting with "_" are reserved for use by the system` 拒绝加载。
> 你自己 clone 下来是干净的；如果你在里面放了调试文件，注意别用 `_` 打头。

改完源码要让改动生效：在 `chrome://extensions` 点扩展卡片上的**刷新 ↻**（不用重启浏览器），然后把已经开着的网页 `F5` 一次。

## 第一次用

装完是**空字典**——仓库里不含任何人的信息，这一点是刻意的。

扩展选项页会弹一个初始化向导，你把自己那几条常用信息填一遍（敏感项标了"选填·只存本机"）。懒得填就点「跳过，边用边记」，用着用着自然就攒起来了。

## 隐私这块我说清楚

这东西要读你在所有网站上的表单，所以我必须把话说透，你自己也能验。

**它是什么**

- 唯一申请的能力是 `storage`，数据只进 `chrome.storage.local`——就是你这台机器的这个浏览器
- 出厂**不含任何个人信息**。仓库和演示一律假名（张三 / 138xxxx0000 / you@example.com）
- 没有账号、没有云同步、没有遥测、没有检查更新

**它没有什么**

- 代码里没有 `fetch` `XMLHttpRequest` `WebSocket` `sendBeacon` `EventSource`
- 没有 `chrome.storage.sync`（这个会把数据同步到 Google 云端，是最容易踩的坑）
- 没有 `host_permissions` `tabs` `cookies` `webRequest`

**为什么要全站匹配**

`manifest.json` 里写的是 `"matches": ["http://*/*", "https://*/*"]`，所以装的时候 Chrome 会提示"读取和更改您在访问的网站上的所有数据"。

这是没法避免的：网申系统散落在各家域名（国聘、南方电网、中粮、各种招聘站…），没法预先枚举，不全站注入就没法在你点输入框的时候弹卡片。这是本扩展唯一的"重权限"，也是最该被质疑的一条，所以我把它摆在这儿。

如果你只投那么几家，可以自己把 `matches` 改成白名单，代价是别的站就不支持了。

**你自己怎么验**

- `chrome://extensions` → 本扩展「详情」→ 看权限一栏，对照上面写的
- 任意网页按 `F12` → Network → 筛选 **Fetch/XHR** → 然后点输入框、点候选填入、点记住。**应该一条请求都没有**
- 源码全在这儿，自己搜也行：`grep -nE "fetch\(|XMLHttpRequest|WebSocket|sendBeacon|storage\.sync|host_permissions" *.js manifest.json` 应该是空的
- `tests/unit.html` 里有一条 T7 断言会持续扫源码守这条线，命中就测试失败

**一件要提醒的事**

「字典管理」页的导出备份 JSON **含你的真实信息**。要备份请只放在本地，别提交、别上传、别转发。仓库的 `.gitignore` 已经把 `private/` 排除了，就是为这个。

另外，Chrome 自带的地址自动填充是另一条独立通道，跟本扩展无关；如果你用了浏览器保存的地址，那是 Chrome 在管。

## 已知限制：识别率不可能是 100%

表单识别靠读输入框附近的文字信号。有些情况下**信号本身在 DOM 里就不存在**，任何只读 DOM 的工具（包括 Chrome 自带填充、1Password 这些商业产品）都没辙：

- 标签用 CSS 伪元素（`::before` / `::after`）渲染的——文字不在 DOM 里
- 纯图标输入框、没有文字占位的自定义控件
- 整张表用 canvas 画出来的——DOM 里根本没有输入框

要补上这类信号得让程序"看截图"，那就得引入视觉模型、得联网，与"零联网"冲突。这条我明确不做。

**但认不出来不等于不能用**，前面说的「＋ 记住」就是兜底：第一次手动填一下，之后这个站这类框就自动有了。

能修的我会持续修。遇到新的一类 DOM 结构（比如组件库把标签做成旁支兄弟元素）就补一层通用规则；站方话术缺词就往 `concepts.js` 里补。识别率是单调往上走的，但永远到不了 100%。如果你碰到没认出来的框，欢迎提 issue，附上那个框的标签文字和页面链接。

## 想让它认得更准：改概念表

`concepts.js` 是唯一需要长期扩充的地方。某类框总归位不准，就往对应概念里补个词，不用动逻辑：

```js
{ id: 'phone', label: '手机号', person: true,
  zh: ['手机', '电话', '号码', '移动'],      // 往这里加中文近义核词
  en: ['phone', 'mobile', 'tel', 'contactnumber'] }
```

两条规则：中文用"短核词"（标签被完整包含就算命中）；**别往这张表里写任何真实个人信息**。

## 自己跑测试

```bash
python -m http.server 8777         # 在仓库根目录

# 逻辑层（概念表 / 匹配 / 迁移 / 零联网自检 / 过度匹配抑制 / 清洗契约）
# 浏览器打开 http://localhost:8777/tests/unit.html          期望 66/66

# 端到端（chrome.storage 垫片驱动真实 content.js）
# 打开 http://localhost:8777/tests/integration.html
# 控制台执行 window.__itest()                               期望 20/20

# 标签识别 / 写入诚实性 / 危险候选
# 打开 http://localhost:8777/tests/labels.html
# 控制台执行 window.__ltest()                               期望 fail 0
```

URL 后面加个 `?v=` 之类可以避开浏览器缓存，改完源码建议带上。

改 `content.js` 想快速验证又不想反复重启浏览器的话，仓库里有个隔离 harness：

```bash
python tools/cdp_eval.py --url "http://localhost:8777/tests/labels.html?v=1" --expr "window.__ltest()"
python tools/cdp_file.py --file tools/probe/shell.js --url "http://localhost:8777/tests/harness_shell.html?v=1"
```

`tests/harness_shell.html` 把被测代码放进 `srcdoc` iframe（`about:blank` 来源）。已安装的扩展不会注入那里，所以测到的一定是仓库里的源码，而不是浏览器里那份旧实例。探针会自检并回报 `extensionInjected:false`。
