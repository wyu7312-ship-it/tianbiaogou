# 网申填充助手 · WSA Autofill

> 点一下输入框，弹出你存过的信息，点一下就填进**这一个**框。纯本地、零联网的 Chrome 填表助手。

秋招 / 考公报名 / 各种网申系统，同一份简历要重复填几十遍，而且**每个网站的字段叫法都不一样**（手机号 / 手机号码 / 移动号码 / Contact Number…），多人信息还容易串（本人姓名、母亲姓名、紧急联系人…）。这个扩展就是来解决这三件事的。

## 它解决什么

| 痛点 | 别的自动填充 | 本项目 |
|------|------------|--------|
| 每站字段话术不同 | 按 label 精确匹配，换个词就失忆 | **概念表 + 同义词**：中英文近义标签自动归位到同一概念 |
| 一个"姓名"框背后有多个人 | 只能记一个值 | **人称 scope**：本人 / 母亲 / 父亲 / 紧急联系人 各存各的，卡片并列给你挑 |
| 批量自动填容易错位 | 一键灌完整张表 | **只填当前框**：点中选中的那个，永不批量、永不自动提交 |

## 设计哲学（三条铁律）

1. **点选防错位** —— 永远是"你点卡片上的某一行 → 只填当前这一个框"，不做任何"猜你要哪个"的自动代填；多个候选一律全列出来带标签，人来决定。
2. **零联网** —— 全部数据只存 `chrome.storage.local`（本浏览器本机）。代码里没有 `fetch` / `XHR` / `WebSocket` / `sendBeacon`，manifest 权限只有 `storage`。有单元测试持续守住这条（见下）。
3. **自填零携带** —— 扩展出厂**不含任何个人信息**。第一次打开是一页初始化向导，你自己填一遍（或直接跳过、边用边记）；仓库与演示一律用假名（张三 / 138xxxx0000 / you@example.com）。

## 安装（Chrome 152：只能手动加载未打包）

1. 下载 / clone 本仓库到本地某个目录。
2. Chrome 打开 `chrome://extensions` → 右上角开启**开发者模式**。
3. 点**「加载已解压的扩展程序」**→ 选择本仓库根目录（含 `manifest.json` 的那层）。
4. 改了源码后：`chrome://extensions` 里点该扩展卡片上的**刷新 ↻** 按钮即可生效（无需重启浏览器）；已经打开的网页按 `F5` 刷新一次换上新脚本。
5. 首次点击输入框前，建议先去扩展「详情 → 扩展程序内容 / 字典管理」跑一遍初始化向导。

> ⚠️ 命令行 `--load-extension` 在 Chrome 152 已被侧载保护静默忽略，不要再走那条路。

## 怎么用

- 在任意网申页**点中一个输入框** → 旁边弹出候选卡片（可拖动标题栏移位，双击标题栏恢复自动定位）。
- 有候选：点一行，或 `↑`/`↓` + `回车` → 填入当前框，填完请目检。
- 没候选：手动填好该框 → 点卡片底部的**「＋ 记住」**→ 下次同类框自动有候选。
  - 新说法（如"移动号码"）会**自动归位**到已有概念；识别不了的独立成一个字段，不会污染别的框。
  - 涉及"母亲/父亲/紧急联系人"等限定词的框，记住时会打上对应 **scope 标签**。
- 「字典管理」页可编辑别名 / 候选值 / 标签，导入导出 JSON，或**一键清空本机字典**（二次确认）。

## 已知限制：识别率为什么不可能 100%（请先读这段）

表单字段识别靠读取输入框附近的文字信号（label / placeholder / 紧邻元素 / 表格单元）。以下情况**信号本身就不存在**，任何只读 DOM 的工具（包括 Chrome 自带自动填充、1Password 等商业产品）都无法识别，本项目亦然：

- 标签由 CSS 伪元素（`::before` / `::after`）渲染——文字不在 DOM 里；
- 纯图标输入框、无文字占位的自定义控件；
- 表单被 canvas 整体绘制，DOM 里根本没有输入框。

要靠"看页面截图"补上这类信号就得引入视觉模型，与本项目的零联网铁律冲突，明确不做。

**但"识别不出"≠"用不了"，本扩展的交互天生为此兜底**：

1. 最坏情况 = 卡片弹出但标题为空 → 你照样打字进框 → 点**「＋ 记住」**→ 值已入字典；
2. 记住时该框的标签文字自动进别名表，**同站同类框第二次就自动命中**；
3. 因此每个陌生字段的第一次代价只是多点一下，之后渐愈。

能修的我们会持续修：采集策略遇到新一类 DOM 结构（如组件库把标签做成旁支兄弟元素）就补一层通用规则；站方话术缺词就往 `concepts.js` 补。识别率单调上升、无限逼近，但不会"到达 100%"——介意的请先掂量，欢迎提 issue 附上没认出的框的标签文字与页面链接。

## 概念表维护（唯一需要长期扩充的地方）

`concepts.js` 是一张"概念 → 中英同义词"表。遇到某类框总归位不准，就往对应概念补一个词即可，无需改逻辑：

```js
{ id: 'phone', label: '手机号', person: true,
  zh: ['手机', '电话', '号码', '移动'],      // 往这里加中文近义核词
  en: ['phone', 'mobile', 'tel', 'contactnumber'] } // 英文一律小写、去空格
```

规则：① 中文用"短核词"（标签被完整包含即命中）；② 禁止往这张表里写任何真实个人信息。

## 隐私声明

- 数据只在**你这台机器的这个浏览器**里（`chrome.storage.local`），不使用 `storage.sync`、不上传、不遥测、不检查更新。
- 出厂零携带：仓库里没有任何使用者个人信息；演示与测试全用假名。
- 备份 JSON（导入导出用）**含个人信息**，请只存进本地 `private/`（已被 `.gitignore` 保护），切勿提交、上传或转发。
- 提示：Chrome 自带的地址自动填充是**另一条独立通道**，与本扩展无关；若你用了浏览器保存的地址，那是 Chrome 在管理，不经过本项目代码。

## 免重启验证改动（调试用）

改 `content.js` 后正式生效需重启浏览器（未打包扩展启动时才重读文件）。
调试时可用隔离 harness，不必反复重启：

```bash
python tools/cdp_eval.py --url "http://localhost:8777/tests/labels.html?v=1" --expr "window.__ltest()"
python tools/cdp_file.py --file _probe_shell.js --url "http://localhost:8777/tests/harness_shell.html?v=1"
```

`tests/harness_shell.html` 把 harness 放进 `srcdoc` iframe（`about:blank` 来源）——
已装扩展不会注入那里，因此测到的一定是本地源码，而不是浏览器里那份旧实例。
探针会自检并回报 `extensionInjected:false`，隔离一旦失效立刻可见。
